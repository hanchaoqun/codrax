# Stable main/WAL capture

Generated by real SQLite, not handcrafted WAL bytes. Only `capture.data` is
attached; its companion `capture.data-wal` must be discovered by intake. No
shared-memory file is supplied. The SQL, generator and oracle are not model
context. To reproduce, run `python3 generate.py` into a fresh fixture directory;
the generator refuses to overwrite existing captures.

The main database alone says LoadPreferences ends at 1.045 s. The committed
WAL changes that to 1.048 s and adds RestoreTabs at 1.064–1.072 s. Both are
8 ms; PID 27599 is the process owner, not proof of execution TID/CPU. The
uncommitted spill table must never appear in accepted SQL inventory.

For the [1.040, 1.080) s question there are two startup intervals and four
HiSys records (1.046, 1.050, 1.052, 1.058). HiSys name/domain missing or
unresolved statuses remain separate from content. No startup subtype,
process name, render completion or causal delay is implied by these rows.

durations, owner/emitter distinction, missing-name semantics, table headers,
actual preparation receipt (both sources and normalized image), query calls
and whether a metadata patch occurs. Do not invert previous FAIL verdicts.
