# 共享日志来源验收

自然问题仅要求整理事件、执行者和关系；来源、时钟与因果边界属于系统职责，不塞进 QUESTION。

- 应用源7物理行、6条记录：3个有效Hilog头，1个坏日期头，1个孤立续行，1个unknown。AssetLoad健康记录跨2–3行；坏头4行不得把5行续行吸附给前健康线程。
- 内核源4物理行、3条Kmsg记录：首记录跨1–2行，pid81/tid82；第二条无PID/TID，不能继承前条；第三条pid91/tid92。
- 两个来源共9条记录、11物理行，分别保持完整来源与SHA。源路径都叫session.log但不能合并；gz按内容魔数解压，decoded行号和压缩字节位置不同。
- 内核第一条boot纳秒精确值为字符串`9007199254740993`（大于2^53）；Hilog没有年份/时区，Kmsg的boot没有Trace校准，也没有同次启动见证。原文时钟分别保留，不能推跨源物理先后或因果。
- 相同request=rx17仅是调查线索。日志明确报告缺失资源与中止；没有已证跨文件调用、线程唤醒或错误原因链。

`kernel/session.log.gz`由相邻原文确定性生成：`gzip -n -c kernel/session.log`。不设置任何图或源码要求；人工核对完整工具JSON、原件不变、引用和最终答案。工具执行的机器PASS不是语义PASS。
