它是什么

一个会读仓库、会追证据、会给引用的分析助手

不是“模型直连仓库”的聊天壳，也不是靠文风自信制造正确感的问答器。

可以把它当成什么

  • 熟悉陌生系统、线上排障、架构讲解的工程工作台。
  • 审批后能在沙箱里走完整改动闭环的变更助手。

不该把它当成什么

  • 不是无约束的“让模型自由发挥”问答。
  • 不承诺“永远秒答”——它承诺的是可复核。

一个正确预期

  • 能证实的尽量证实，证不实的明确标边界。
  • 价值在于更稳地把复杂问题拆清楚。
核心特性

为什么它的答案值得信

每一项特性都指向同一件事——让结论可被复核，让不确定被说清。

证据锚定的答案

每条结论都带 file:line 引用，经 7 层落地校验；编造或与源码不一致的引用会被隔离，不入正文。

确定性流水线

模型只在很窄的位置参与；调查顺序、停止条件、答案放行都由固定代码接管，同样的问题走同一套闸门。

日志 / 性能现场分诊

挂上崩溃日志或 HiTrace / atrace / perfetto，先抽成结构化锚点，再让主流水线只读真正相关的文件。

写模式沙箱

计划 → 改动 → 验证 全程在 git worktree 里跑，主仓 HEAD 永不自动变；只有你显式批准才落地。

跨仓 workspace

父目录下多个独立 git 仓共存时自动发现，跨子仓查询正确，内存可控，单仓用户零影响。

多语言 · 多 runner

覆盖十余种语言的代码索引；写模式验证自动探测 12 类测试工具，零测试发现不会被误判为失败。

它怎么工作

不是把问题丢给模型，而是编成一条调查协议

模型负责读现场、交阶段结果；系统负责决定证据是否成立、流程是否继续、答案是否放行。

用户请求→ 轻量预扫→ 分析清单→ 调查→ 提炼→ 验收→ 带引用的答案

模型被限制在很窄的位置

分析阶段只能轻量预扫，确认仓里有没有这个对象；它必须把问题写成结构化任务单，写不出来就停下。

调查、提炼、成稿彼此隔离

调查只交事实，提炼只做判断，成稿只负责表达。没读到的文件，后面没有权限“脑补”进答案。

快速上手

四步从零跑起来

最快的方式是下载预编译发布包；想自己构建也只多一步。完整说明见使用手册。

1

获取 codrax

git clone https://github.com/hanchaoqun/codrax.git
cd codrax && make   # 或到下载页取预编译包

下载预编译发布包免构建、最省事；源码构建需要 CGO（macOS 先 xcode-select --install）。

2

加进 PATH

echo 'export PATH="/path/to/codrax:$PATH"' >> ~/.bashrc   # bash
echo 'export PATH="/path/to/codrax:$PATH"' >> ~/.zshrc    # zsh
exec "$SHELL" -l

之后在任何目录都能直接敲 codrax 启动。

3

配置 providers.yaml

cp providers.yaml.example providers.yaml
# 填 api_key + model，和二进制放同一目录

连接 LLM 凭证，支持任何 OpenAI 兼容服务：OpenAI / DeepSeek / Qwen / 本地 vLLM / Ollama。

4

cd 进仓库再启动

cd /path/to/your/repo   # 先进入要分析的项目
codrax                  # 再启动交互控制台

答案带 file:line 引用；/help 列出全部斜杠命令。

⚠ codrax 把「当前目录」当作要分析的代码仓库。 使用前务必先 cd 进你的项目根目录再运行 —— 它分析的就是你启动它时所在的那个目录，运行产物也都写在该目录的 .codrax/ 子目录下。
