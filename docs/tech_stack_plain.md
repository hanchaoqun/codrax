# Codrax 关键技术清单（通俗版）

面向非专业读者的一页纸介绍：Codrax 用了哪些技术、为什么要这些、它们如何串成一条完整的只读代码分析流水线。

## 核心技术

1. **Go 语言** — 一门编译型静态类型语言，跑得快、打出来就是一个可执行文件，不用装运行时。
2. **LLM（大语言模型）** — 项目的"大脑"，所有需要理解自然语言问题和代码语义的地方都交给它。
3. **ReAct 循环** — 让 AI "边想边动手"：看一眼、决定下一步、再看一眼，像人调查问题一样迭代。
4. **多智能体协作** — 4 个专职小 AI（分析员 / 探查员 / 提取员 / 成稿员）接力干活，每个只管自己那一棒。
5. **4 阶段流水线** — 问题走固定的四步：先看懂题 → 去翻代码 → 整理证据 → 写成答案，不允许跳步。
6. **Tool Use（函数调用）** — 教会 AI "只能点菜单上的菜"：读文件、搜关键词、列目录这些工具由代码提供，AI 只能按格式调用。
7. **JSON Schema 约束** — 给 AI 的输出套上"填表模板"，它必须老老实实按字段填，不能自由发挥。
8. **DAG 任务图** — 把复杂问题拆成一张有方向的任务网，节点之间有依赖关系，调度器按依赖顺序推进。
9. **假设驱动规划（HDP）** — AI 先列"可能的答案是什么"，再反过来去找证据验证，像侦探破案。
10. **证据锚定（Grounding）** — AI 说的每句话都要回到"源码第几行"，找不到就标"未证实"，杜绝瞎编。
11. **引用闭环（CGEC）** — 4 条铁律保证"引用的文件必须真读过、链条不能断、数量不能缺"。
12. **Criterion 可执行合约** — 把"什么算做完"翻译成 19 种可代码判定的检查项，机器自己判作业。
13. **ripgrep / grep 搜索** — 业界最快的代码搜索工具，几百万行代码里秒级找关键词。
14. **YAML 配置** — 用人类可读的文本文件配参数，改一行就能调行为，不用重新编译。
15. **Glamour 渲染** — 把 AI 写的 Markdown 答案美化成带颜色、加粗的终端输出。
16. **pterm 终端 UI** — 实时刷新进度条和任务树，让你看到 AI 当前走到哪一步。
17. **文件锁（flock）** — 多个 codrax 同时跑时，用系统锁防止它们抢同一个记忆文件写坏。
18. **Blob 大对象存储** — 工具输出太长就存成文件返回摘要，不把 AI 的上下文塞爆。
19. **FNV32 命名空间** — 用仓库路径算哈希做目录后缀，不同仓库的日志和记忆自动不串台。
20. **REPL 交互** — 像 Python 解释器那样开个对话窗口，连续问多个问题不用每次重启。
21. **日志轮转** — 日志满 4MB 自动切新文件、只留最近 7 份，不会无限吃磁盘。
22. **Prompt Skill 模块** — 每个阶段一份"岗位说明书"（markdown），改 AI 行为不用动 Go 代码。

## 整体流程图

```
┌─────────────────────────────────────────────────────────────────┐
│  用户提问  →  REPL / CLI  →  加载 codrax.yaml + providers.yaml  │
└──────────────────────────────┬──────────────────────────────────┘
                               ▼
                    ┌──────────────────┐
                    │  读取历史对话     │ ← 记忆存储 (MEMORY.md)
                    └────────┬─────────┘
                             ▼
╔════════════════════════════════════════════════════════════════╗
║                   4-stage 流水线 (orchestrator)                 ║
╠════════════════════════════════════════════════════════════════╣
║                                                                 ║
║  ┌──────────────┐                                               ║
║  │ ① analyze    │  分析员 AI：看懂题目                          ║
║  │  (analyzer)  │  ─ 扫一眼仓库结构 (repo_map)                  ║
║  │              │  ─ 产出 AnalysisIR (任务图+证据计划+合约)     ║
║  └──────┬───────┘                                               ║
║         │ 质量门 (7 项检查) ✓                                   ║
║         ▼                                                       ║
║  ┌──────────────┐       ← 按 TaskGraph 依赖调度                 ║
║  │ ② explore    │  探查员 AI：去翻代码 (Turn A)                 ║
║  │  (explorer)  │  ─ ripgrep + read_file 找证据                 ║
║  │              │  ─ 每条证据必须锚到源码行号 (Grounding)       ║
║  │              │  ─ 可反复多轮，直到 HasEnoughFacts            ║
║  └──────┬───────┘                                               ║
║         │                                                       ║
║         ▼                                                       ║
║  ┌──────────────┐                                               ║
║  │ ③ extract    │  提取员 AI：整理 (Turn B, 只跑一次)           ║
║  │  (extractor) │  ─ 把散的证据结构化成符号+假设判定            ║
║  └──────┬───────┘                                               ║
║         │                                                       ║
║         ▼                                                       ║
║  ┌──────────────┐                                               ║
║  │ ④ finalize   │  成稿员 AI：写最终答案                        ║
║  │  (finalizer) │  ─ emit_answer_document 一次填表              ║
║  │              │  ─ 引用闭环 CGEC 校验 → 不过就退回重试        ║
║  └──────┬───────┘                                               ║
║                                                                 ║
╚═════════╪═══════════════════════════════════════════════════════╝
          ▼
   ┌───────────────┐
   │ Glamour 渲染  │ → 彩色 Markdown → 终端
   └───────────────┘
```

**关键节点校验**：每阶段结束都会过"合约检查"，不合格就回炉重做（预算内），保证答案有据可查、不是 AI 幻觉。
