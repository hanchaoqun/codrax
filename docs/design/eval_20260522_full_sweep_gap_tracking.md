## Systemic Root Cause Consolidation

The 9 hard failures plus the pass-with-gap runs collapse into architecture
families rather than isolated cases:

1. **Structural inventory is still too LLM-driven.** `u8b`,
   `read_combo_criterion_rich_functions`, `qf_multi_member_set_count_caveat`,
   and related pass-with-noise cases ask for bounded source inventories. The
   current pipeline can preserve rich summaries once evidence lands, but it
   still asks the model to discover complete member sets manually. This causes
   over-inclusion, omissions, and stale grouped counts. Required direction:
   reuse repo-map / language parsers / structural indexes to produce candidate
   sets, then let the model enrich and explain. Do not replace model-authored
   prose; only supply typed membership authority.
2. **Origin/citation boundaries are not fully consolidated.** VCS, command,
   log, trace, and runtime observations are now represented in the observation
   ledger, but some finalizer payloads and supplements still rely on
   `citation_ref=-1`, pseudo `file:0`, or closure prose for load-bearing
   support. Required direction: keep `citations[]` current-source only and
   route non-source provenance through origin-specific observation refs and
   localized support text.
3. **Analyzer hard gates still conflate discovery inventories with named-entity
   enumerations.** Package-scope inventories often name one example or one
   scope entity, then ask the system to discover all matching members. The L0-B
   cardinality gate can still reject that shape before exploration. Required
   direction: use typed scope / answer-visibility / required-file hints to
   recognize source inventory questions without weakening true category
   enumeration contradictions.
4. **Small schema slips still consume model rounds.** `anchor_kind` /
   `evidence_kind` near-misses and finalizer JSON-shape repairs are mechanical
   defects. When the payload has a valid source/line and the repair is
   lossless, the system should repair locally and record telemetry; broad
   invalid shapes must still fail loud.
5. **Closure and aggregate facts can outrank richer grounded evidence in a few
   downstream paths.** `StableInvestigationAggregateFacts()` and summary merge
   protections exist, but some validators/materializers still treat grouped
   counts or closure prose as answer-grade. Required direction: all consumers
   should prefer grounded, in-scope, read evidence and ledger records with rich
   summaries; aggregate facts organize or supplement, not replace, principal
   evidence.
6. **Runtime/status and repo-map concurrency issues obscure true progress.**
   Several runs show transport retries mislabeled as semantic rewrite and
   repo-map wall-clock waits outside progress accounting. These are UX and
   reliability gaps, not answer-contract changes, but they directly affect
   commercial perception.

## Architecture Remediation Decision

Decision: **A — architecture remediation is required before more case-level
fixes.** The repo already contains the main reusable contracts:

- `ObservationLedger` and `types.PrioritizeObservationRecords` for
  origin-aware evidence handoff.
- `AnswerIntentContract`, `AnswerVisibilityProfile`, claim bindings, and
  current-source citation eligibility helpers for typed answer shape.
- `StableInvestigationAggregateFacts()` and rich-summary merge guards for
  accepted aggregate state.
- `emit_evidence` schema compatibility and source-grounding machinery.

The next work should therefore tighten these existing contracts instead of
adding parallel mechanisms.

Architecture decision:

- Do not add a parallel answer surface. The existing
  `emit_investigation_complete` aggregate-facts lane remains the only stable
  handoff to extractor/finalizer. The existing
  `reconcileCompletionAggregateFactsWithDefinitionEvidence` pass already

  overwrite model-authored rich summaries. Existing evidence-summary merging

  for preserving the explorer's narrative detail.
- Structural candidates are append/reconcile inputs, not finalizer rewrite
  triggers. If a candidate cannot be generated with parser/graph certainty, it
  becomes a localized supplement or remains unknown; it must not force a late
  finalizer retry.
