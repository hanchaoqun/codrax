## 1. 第一性与排序键定稿论证(七问①)

### 1.1 客户第一性与三块语义基石(出处:方案1 §1,评审确认为三稿最完整)

客户工程师的问题是:**「消除什么、这个窗口能好多少 ms」**。回答它的量已存在且已是单一权威:`rootCauseEffectiveImpactMs`(query.go:12272 起)= 窗内折算后有效归因——runnable 全额 / running 供给折算缺口(0 权威)/ 语义 span 链窗交集 / VS-1 周期源折减 / D/IO 全额(§29.27 canonical 裁定①)。

- **基石 A(同尺前提)**:E-Gap③ 保证 aggregate_only 主体永不判 adjacent——链上与 ◇ 的**数值**同尺(目标线程窗内墙钟 ms),跨通道**并列**不踩两把尺红线。但 4165 给出行级反例(◇ 内页缓存抖动 0.600 = 计数当量),故两把尺必须**下沉到行级守卫**(→V2-P0,§6)。
- **基石 B(数值语义分档)**:同一把尺上,链上行 eff=**已证可消除量**;◇ 行 eff=**条件可消除上界**(因果候选成立时至多好这么多)。同单位、同窗轴、可比大小;差别在断言强度——断言强度由身份词表达,不由分离的数值空间表达。**数字同尺,条件入词面。**
- **基石 C(可消除量在目标线程上定义)**:▒ 行(跨线程 cpu·ms/他线程墙钟)没有定义好的窗内可消除量——消除 SearchDaemon 的 54.701ms 不会让目标窗口好 54.701ms;其真凶成分已经供给折算/runnable 全额皮带在链上重表达。**第一性本身把 ▒ 排除在汇排外,无需借助身份论证。**
